<objective>
Implement the three backtest API routes: the batch-fetch endpoint that returns one JSON payload (instruments + prices + dividends + fx_rates + snb_rates + prices_version), the runs write/list endpoint, and the single-run reload endpoint with stale-on-view detection.

Purpose: These are the data plane between the database and the worker. The worker is sandboxed (no DB access); the UI is RLS-scoped (no service-role); these routes are the only path from authenticated client to cached data. Plan 05 (worker) reads from these endpoints; Plan 06 (UI) calls them on form submit and on history-row click.

Output: Three Next.js 16 App Router route handlers, one Zod schemas module.
</objective>

<interfaces>
Request/response shapes (consumed by Plan 05 worker client + Plan 06 UI):

POST /api/backtest/data — Request body (Zod-validated): { portfolio_id (UUID), benchmark_ticker (string|null, must be in whitelist), start (ISO date), end (ISO date) }.
Response 200: { items, benchmark, prices, dividends, fxRates, snbRates, pricesVersion (epoch ms), investmentAmount }.
Errors: 401 unauthorized, 400 invalid_input, 404 not_found, 503 transient — all in DataError shape.

POST /api/backtest/runs — Request body: { portfolio_id, params (BacktestParams), inputsHash (hex64), pricesVersion (int), output (BacktestOutput) }.
Response 200: { id, deduped (boolean — true when upsert hit existing inputs_hash) }.
Errors: 401, 400, 503.

GET /api/backtest/runs?portfolio_id={uuid} — Response 200: Array of { id, portfolio_id, params_json, metrics_json, prices_version, computed_at } ordered by computed_at DESC.

GET /api/backtest/runs/[id] — Response 200: { ...RunRow, stale: boolean } where stale = stored pricesVersion < currentPricesVersion. 404 if RLS hides the row.

Zod schemas in src/lib/backtest/api-schemas.ts:
- BacktestDataRequestSchema — portfolio_id is UUID, start/end ISO date, start ≤ end, (end - start) ≤ 25 years, benchmark_ticker in BENCHMARK_TICKER_WHITELIST or null
- BENCHMARK_TICKER_WHITELIST — D-22 candidates: URTH.US, SWDA.LSE, SSAC.SW, ACWI.US, SPY.US, CSSMI.SW
- BacktestRunWriteSchema — portfolio_id UUID, params shape, inputsHash matches /^[0-9a-f]{64}$/, pricesVersion non-negative int, output structured

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → /api/backtest/* | Untrusted JSON; Zod validates shape, RLS validates ownership |
| Untrusted portfolio_id | IDOR risk if RLS not enforced |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-04-IDOR | Information disclosure | /api/backtest/data accepting arbitrary portfolio_id | mitigate | RLS on portfolio_instruments + portfolios enforces ownership; we use createClient() (SSR cookies-bound, not service-role); .maybeSingle() returns null when RLS hides the row → 404 |
| T-5-04-DOS | Denial of service | huge date range (50yr * 20 instruments = 250K rows) | mitigate | BacktestDataRequestSchema refine: yearsBetween(start, end) <= 25; Zod 400 returned before DB hit |
| T-5-04-SSRF | Server-side request forgery | benchmark_ticker triggers external fetch | mitigate | benchmark_ticker is z.enum(BENCHMARK_TICKER_WHITELIST) — no arbitrary tickers; route only does Supabase reads, never external fetch |
| T-5-04-COLL | Tampering | inputs_hash collision loads wrong cached run | accept | SHA-256 cryptographic; collision probability negligible at human scale (RESEARCH §Security Domain) |
| T-5-04-STORE | Denial of service | unbounded backtest_runs writes | accept | CONTEXT decision: 'keep all' for v1; LRU cap deferred. Solo developer scale → unlikely to fill quota |
| T-5-04-RUN-LEAK | Information disclosure | GET /api/backtest/runs leaks other users' runs | mitigate | RLS on backtest_runs (Plan 01 migration 00009 — 3 policies gated on auth.uid() = user_id); createClient() not service-role |
| T-5-04-IDOR-ID | Information disclosure | GET /api/backtest/runs/[id] reveals existence of someone else's run | mitigate | .maybeSingle() returns null under RLS → 404; same response shape as 'truly does not exist' so existence is not disclosed |
</threat_model>
