src/app/dashboard/backtest/BacktestClient.tsx ('use client'):
Props: { portfolios: PortfolioListItem[], benchmarks: BenchmarkOption[] }
State: { phase: 'idle' | 'fetching' | 'running' | 'done' | 'error', params: BacktestParams, batchData: BatchDataResponse | null, output: BacktestOutput | null, runId: string | null, isStale: boolean, error: BacktestError | DataError | null }
- useBacktestWorker hook from Plan 05.

**State machine (explicit):**
- States: `idle` | `fetching` | `running` | `done` | `error`
- Transitions:
  - `idle → fetching` on first param-set (or any heavy-param change while idle)
  - `fetching → running` on `/api/backtest/data` response arrival (batchData populated, worker.run() invoked)
  - `running → done` on worker result; POST `/api/backtest/runs` and capture run.id
  - `running → fetching` if a heavy-param change arrives mid-run: call `worker.terminate()` + recreate the worker via the hook's terminate+restart path, then fetch new data
  - `done/running → running` if a cheap-param change arrives: skip fetch, call `worker.run()` again with cached batchData + new params
  - `* → error` on any fetch failure (DataError) or worker reject (BacktestError); render an inline retry banner with a Retry button that transitions `error → fetching` (heavy params) or `error → running` (cheap params)

**Heavy params (trigger fetch + worker rerun):**
- `portfolio_id`
- `benchmark_ticker` (changes the set of instruments fetched per Plan 04 batch endpoint)
- `start`
- `end`

**Cheap params (worker rerun only, no fetch):**
- `drip`
- `rebalance`

NOTE: `benchmark_ticker` is intentionally classified as heavy because changing the benchmark requires the API to include that ticker's prices in the batch payload. If the executor confirms the Plan 04 endpoint pre-fetches ALL D-22 benchmarks in a single payload, `benchmark_ticker` may be downgraded to cheap — document the decision in the file-level doc comment.

- After worker.run resolves: POST /api/backtest/runs with { portfolio_id, params, inputsHash, pricesVersion, output }, store run.id; render <BacktestResults output={output} params={params} />
- Render <RunHistoryDrawer portfolioId={params.portfolio_id} currentRunId={runId} onSelectRun={loadHistoricalRun} />
- loadHistoricalRun(runId): GET /api/backtest/runs/[id], setState with loaded params + output + isStale flag; transitions `* → done` (no fetch, no worker).
- Default params: portfolio = first in list; start = max(10y ago, latest first_date across selected portfolio's instruments — sourced from props.portfolios[0].instruments[].first_date, no second round-trip needed); end = today; drip = false; rebalance = 'annual'; benchmark_ticker = null (D-03).
- `earliestAllowedStart` computed inline from `Math.max(...portfolio.instruments.map(i => Date.parse(i.first_date)))` and passed as a prop to BacktestSetupBar.
